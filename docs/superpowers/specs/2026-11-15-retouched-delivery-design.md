# 精修后的照片：交付、对比、下载与反馈

日期：2026-11-15
状态：用户已确认书面设计并授权开发、上传和上线；开发与测试完成，已通过两轮独立审查，待部署上线。

## 已确认的需求

- 本次交付归属正式订单 **#1「廖府」**。
- 文件来自 `/Users/chigo.liao/Documents/爸妈摄影/精修后/已修`，22 张 JPEG，约 135 MiB；单张约 4.3–8.8 MiB，尺寸为 3840×5760 或 5760×3840。
- 新增独立功能，客户入口名称为 **“精修后的照片”**，沿用当前知更鸟蓝界面。
- 精修照片原文件高清查看、放大、单张下载及全部打包下载，不额外压缩或加水印。
- 修前对比使用订单中现有的未修图片。现有图片约 500–1170 像素，含原有水印；界面明确提示其清晰度低于精修文件。
- 可以对某一张、某一版精修提交反馈，影楼可以回复。默认仅影楼可见，可选择订单内公开。
- 不覆盖原片，不改变订单现有选择、产品指定、权限、截止时间或选片状态。

## 方案取舍

采用独立交付页面，不把精修当作原片替换。相较在选片大图中堆叠功能，独立页面可以区分选片讨论与修图反馈，并在重新修图后保留版本记录。此次不增加图片涂画标注、自动人脸识别、满意度评分或整单确认交付流程。

## 客户界面

- 新增订单路由 `/jobs/:id/retouched`，顶部导航“精修后的照片”。没有已发布照片时显示明确空状态。
- 列表使用派生缩略图延迟加载，显示文件名、当前版本、反馈数量；不预加载全部 135 MiB 高清文件。
- 点击进入查看器，默认加载该张精修原 JPEG；有加载状态、错误重试、适应屏幕/放大和上一张/下一张。
- 提供“修前 / 修后”切换及并排模式；手机并排模式上下排列。图片完整 contain 展示，不强行裁切或声称像素级滑块对齐。
- 修前读取已配对原片的现有鉴权预览，不绕过未修原片原有高清下载限制。未配对时仅显示精修并提示“暂未关联修前照片”，禁用对比。
- 单张下载获得原 JPEG；全部下载获得当前已发布版本的 ZIP。微信内置浏览器提供“在浏览器中打开”的提示，不声称自动保存到相册。
- 当前版本可直接反馈；历史已发布版本可查看和下载，旧反馈按版本保留，但仅当前版本允许新建反馈，避免对过期修图提出新任务。

## 后台界面与发布

- 订单新增“精修交付”页：多文件上传、进度/失败明细、原片配对、精修预览、版本列表、发布/撤回和反馈查看回复。
- 上传与发布分开。每张上传先成为草稿，处理成功且关联核对无误后可批量发布。
- 未修图必须属于同一订单；只支持对已有有效未修图建立关联，不跨订单关联。无可靠配对的照片可独立交付，但不提供错误对比。
- 新精修版本以新增不可变记录实现，不覆盖之前版本；发布后成为当前版本。可保留历史已发布版本，撤回版本不得继续被客户访问。
- 同一订单下原文件 hash 完全相同的重复上传可识别并跳过；同名但内容不同按新版本确认，不静默覆盖。
- 本次正式发布通过该功能的业务服务/API执行，不用 SQL 直接伪造交付状态。

## 数据与文件边界

- 完善现有未使用的 `retouched_photo` 占位表，作为精修版本记录。独立保存 job、稳定交付资产标识、对应 photo（可空）、版本、原文件路径、缩略图、hash、文件大小、宽高、处理/发布状态、上传者和时间。未配对照片也有稳定资产标识，新版本仍归属同一交付资产。
- 为同订单关联、同交付资产版本唯一性和当前版本选择建立校验/约束；已有占位数据的升级不得无提示丢弃。
- 精修原文件存于 `data/uploads/retouched/` 独立目录，保留上传字节及 SHA-256；缩略图另存。原文件目录和新增 ZIP 目录纳入既有备份与到期清理规则。
- 精修文件不进入 Git，不放公共静态目录；文件路径及凭据不返回前端、不写入验收报告。
- 既有 photo 不因精修上传发生路径、hash、version 或选片关系变化。回收/永久清理原片时必须显式处理精修关联，不级联误删交付文件与反馈。

## 权限与反馈

- 继续使用现有登录和会话，不建立匿名下载链接。
- 员工按影楼归属授权；客户必须为该订单参与者。草稿/撤回版本、跨订单/跨影楼访问均拒绝，媒体、列表、下载、ZIP及评论保持相同授权边界。
- 精修发布与原片选片状态独立：允许在当前 selecting 状态发布，不自动锁单；发布后允许高清交付和评论，即使订单随后 locked、retouching 或 delivered。
- 复用现有评论交互和可见性语义，在 `photo_comment` 增加精修版本外键，并通过迁移支持无原片关联的精修反馈。原片评论须有 photo；精修评论须有 retouched version，photo 可空但若存在必须与精修版本关联一致。原片旧接口默认只读取原片评论，不混入精修反馈。
- 回复必须绑定同一照片、同一精修版本且父评论对发言人可见；遵守既有本人编辑时限/删除规则，输入长度校验及转义。
- 仅影楼可见的反馈只对作者和影楼可见，公开反馈仅订单成员可见。后台明确显示“原片 / 精修 vN”。
- 首版不增加独立未读红点，避免沿用原片订单级已读游标造成误清除；页面展示有权限查看的反馈数量并可刷新。
- 发布、撤回、配对、新版、反馈等关键写入与审计/事件保持事务一致；记录安全 ID 和业务摘要，不记录文件绝对路径或凭据。

## 文件校验及故障处理

- 上传沿用现有 50 MiB 单文件上限和内容解码校验；首版支持 JPEG/PNG（本次全为 JPEG），不把 TIFF/PSD 改扩展名接受。
- 限制批次数量、并发处理和 ZIP 生成，拒绝路径穿越、符号链接越界和跨影楼 ID；安全文件名及下载头复用现有工具。
- 只有完整写入且缩略图处理成功的资产才能发布。失败返回逐文件原因，临时文件清理且允许重试；上传中断不产生可访问的半文件。
- 批量 ZIP 成员只来自当前有权限的已发布版本，缓存标识包含精修版本/hash，避免重新修图后下载到旧包；下载时再次校验权限和发布状态。
- 浏览器能查看精修原文件就可保存该文件，不提供虚假的“高清查看但绝对禁止下载”开关。
